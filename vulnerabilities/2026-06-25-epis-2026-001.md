# Stored HTML injection in editor resource pickers

Asset names derived from uploaded filenames were interpolated into the asset picker's
`innerHTML`. Stencil names, descriptions, and tags were later found to use the same unsafe
rendering pattern. An authenticated user able to create one of these resources could store HTML
that was rendered when another user opened the corresponding picker.

## Impact

Through `v0.26.0`, and in `v1.0.0-RC1`, the application's Content Security Policy allowed inline
scripts and event handlers. A payload using an injected element with an event handler could
therefore execute in a victim's authenticated editor session. This required the victim to open the
affected picker.

`v1.0.0-RC2` removed `unsafe-inline` from `script-src`; every GA release has shipped with that
strict policy. It blocks the demonstrated event-handler payload and materially mitigates script
execution. Those releases remain in the affected-code range because they continued to create
arbitrary HTML from stored values.

## Severity

This vulnerability is rated **Medium**, CVSS 3.1 score **5.4**
(`CVSS:3.1/AV:N/AC:L/PR:L/UI:R/S:C/C:L/I:L/A:N`). Exploitation requires an authenticated,
low-privileged author to store a payload and another user to open the affected picker. Successful
script execution can expose or modify information available to the victim, but no direct
availability impact was demonstrated.

A victim who combines editor access with tenant administration could potentially be used to create
an API key with additional tenant roles, increasing the confidentiality impact. That conditional
escalation path has not been demonstrated end to end and is not used as the base-score assumption.

## Resolution

The source fix constructs asset cards with DOM APIs and assigns author-controlled values through
safe properties and `textContent`. It escapes author-controlled stencil text before the remaining
HTML template interpolation. Command-boundary validation also rejects markup delimiters and
control characters in asset names, stencil names, and stencil tags as defense in depth.

The fix ([#833](https://github.com/epistola-app/epistola-suite/pull/833), merged as
`0cdaacfced2e49390d218ca538faed5ea7099bcc`) first shipped in **v1.1.0**. Every release from
v0.0.0 through v1.0.1 is affected; upgrade to v1.1.0 or later. Operators who cannot upgrade yet
should keep the shipped strict Content Security Policy and not weaken `script-src`.
