# Jackson parser and databind findings (seven CVEs, 3.1.5 and 2.21.5)

Trivy reports seven CVEs against the Jackson versions the Spring Boot 4.1.1 BOM manages:
`tools.jackson.core` 3.1.5 (Jackson 3, which the suite uses) and `com.fasterxml.jackson.core`
2.21.5 (Jackson 2, pulled in transitively — for example through `app.epistola.exchange:client`).
The BOM also pulls dependencies that ask for Jackson 3.2.x back down to 3.1.5.

| CVE            | Component | Scanner summary                                                        | Fixed in      |
| -------------- | --------- | ---------------------------------------------------------------------- | ------------- |
| CVE-2026-68497 | databind  | CPU denial of service via unbounded numeric parsing                    | 3.1.6, 2.21.6 |
| CVE-2026-89407 | core      | Denial of service via regular expression backtracking                  | 3.1.7, 2.21.7 |
| CVE-2026-89425 | core      | Denial of service via unbounded `StringBuilder` growth                 | 3.1.7, 2.21.7 |
| CVE-2026-91776 | databind  | Denial of service via unbounded cache growth in `TypeDeserializerBase` | 3.1.7, 2.21.7 |
| CVE-2026-91777 | databind  | Denial of service via quadratic forward-reference completion           | 3.1.7, 2.21.7 |
| CVE-2026-19032 | databind  | Uncontrolled URI scheme resolution in `Path` deserialization           | 3.1.6, 2.21.6 |
| CVE-2026-83557 | databind  | Path traversal via incomplete type validation                          | 3.1.6, 2.21.6 |

## Assessment

**Treated as affected.** The REST API, catalog and ZIP import, and the MCP tools all parse JSON
that callers supply, so a parser-level denial of service is plausibly reachable by an
authenticated caller. We did not establish reachability for each finding individually: patch
releases exist on both lines and are drop-in, so we took them rather than argue.

## Remediation

`apps/epistola`, `apps/epistola-demo` and `apps/pdfrender` override the BOM's
`jackson-bom.version` (3.1.7) and `jackson-2-bom.version` (2.21.7). Each app produces its own
boot jar and resolves its own Jackson, so all three carry the pin. The pins come out once the
Spring Boot BOM manages these versions or later.
