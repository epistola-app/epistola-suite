# Published Vulnerabilities

Epistola Suite keeps its vulnerability history in dated, machine-readable Markdown records
under [`vulnerabilities/`](vulnerabilities/). JSON frontmatter (valid YAML 1.2) carries
OSV-compatible metadata; the Markdown body provides the full human-readable explanation.
This index is generated by `scripts/vulnerability_advisories.py`.

Before disclosure, maintainers coordinate and develop the fix in a draft GitHub Security
Advisory and its temporary private fork. After a patched release is available, this
repository becomes the canonical public record and the GitHub advisory becomes its
publication mirror. A GHSA or CVE identifier is added to the record's `aliases` after
assignment.

Vulnerabilities in third-party components we ship — and our assessment of whether
they are reachable here — are recorded under [`vulnerabilities/`](vulnerabilities/)
as `kind: dependency` records, and published as an [OpenVEX](https://openvex.dev)
document with each release. They are not Epistola advisories: they are never
exported as OSV and never mirrored to GitHub Security Advisories. See
[`docs/sbom.md`](docs/sbom.md#assessing-a-scanner-finding).

regenerate this index, run `pnpm vulnerabilities:render`.

## GitHub publication mirror

Do not add an embargoed vulnerability record to a public branch. Prepare it with the
fix in the draft advisory's temporary private fork, then publish it here only when the
patched release and coordinated disclosure are ready.

Synchronization is an explicit maintainer action. The CLI synchronizes records whose
frontmatter sets `database_specific.github.sync` to `true`; run it only as part of the
coordinated disclosure flow:

```console
$ export SECURITY_ADVISORY_TOKEN  # Set its value securely in the shell first.
$ python3 scripts/vulnerability_advisories.py sync-github \
    --repository epistola-app/epistola-suite
```

New records use `state: draft`. Changing the state to `published` makes an explicit CLI
run publish the GitHub mirror, but validation rejects that transition until
`patched_versions` is populated. The CLI never deletes GitHub advisories and never
requests a CVE. The GitHub Actions workflow only validates and exports records; it does
not mutate advisories.

The explicit sync requires `SECURITY_ADVISORY_TOKEN`, containing a fine-grained token
scoped to this repository with only **Repository security advisories: write** permission.
Do not store this token in the repository. Validation, rendering, and OSV export require
no GitHub access.
