# Published Vulnerabilities

Epistola Suite keeps its vulnerability history in dated, machine-readable Markdown records
under [`vulnerabilities/`](vulnerabilities/). JSON frontmatter (valid YAML 1.2) carries
OSV-compatible metadata; the Markdown body provides the full human-readable explanation.
This index is generated by `scripts/vulnerability_advisories.py`.

GitHub Security Advisories are publication mirrors, not the source of truth. A GHSA or CVE
identifier is added to the record's `aliases` after assignment.

| Published  | ID                                                           | Severity | Affected releases   | Patched release | Summary                                          |
| ---------- | ------------------------------------------------------------ | -------- | ------------------- | --------------- | ------------------------------------------------ |
| 2026-06-25 | [EPIS-2026-001](vulnerabilities/2026-06-25-epis-2026-001.md) | High     | 0.0.0 through 1.0.1 | Unreleased      | Stored HTML injection in editor resource pickers |

To validate the records and generated index, run `pnpm vulnerabilities:check`. To
regenerate this index, run `pnpm vulnerabilities:render`.

## GitHub publication mirror

The `Vulnerability Advisories` workflow synchronizes records whose frontmatter sets
`database_specific.github.sync` to `true`. New records use `state: draft`. Changing the
state to `published` publishes the GitHub mirror, but validation rejects that transition
until `patched_versions` is populated. The workflow never deletes GitHub advisories and
never requests a CVE automatically.

The workflow requires the repository secret `SECURITY_ADVISORY_TOKEN`, containing a
fine-grained token scoped to this repository with only **Repository security advisories:
write** permission. Local validation, rendering, and OSV export require no GitHub access.
