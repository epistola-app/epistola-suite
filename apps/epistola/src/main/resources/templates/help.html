Epistola in short

Epistola makes documents, such as letters, invoices, statements and contracts, from templates. You design a template once. Your organisation's applications send Epistola the details of each document, like a name, an amount or a list of items, and Epistola returns a finished PDF.

  1. Design Build a template in the visual editor. No code needed.
  2. Publish Turn your changes into a release with a number, such as v1.2.0.
  3. Deploy Choose which release an environment, such as Test or Production, uses.
  4. Generate Applications ask for documents, and Epistola makes them from what is deployed.
Changing a template is safe. Your changes are saved as you work, but applications keep getting what they got before, until you publish a release and deploy it.

Words you will meet

Tenant
Your organisation's own space in Epistola: everything you see belongs to it. Work for more than one? Use Switch tenant in your account menu.
Catalog
A collection of templates and everything they are built from. A catalog is published as a whole, with one version number.
Template
The design of one kind of document, such as an invoice or a reminder letter.
Variant
Another version of the same template, for a different language, brand or audience. Attributes, like "language", say which variant is which.
Data contract
The details a template expects from the application, such as a customer's name. It holds example data, so you can see the document before any application sends real data.
Stencil
A piece used in many templates, such as a letterhead or a footer. Change it once, and every template that uses it follows.
Theme
Fonts, colours, page size and margins, shared by the templates that use it.
Next release
Your work in progress on a catalog. Every change you make goes here, until you publish it.
Release
A catalog as it was when it was published, with a number such as v1.3.0. A release never changes, so you always know what an application got.
Environment
A place where applications get documents, such as Test or Production. Each one uses the releases deployed to it.
Deploy
Letting an environment use a release. Undeploying takes it away again.
API key
The secret an application uses to ask Epistola for documents.
Read-only catalog
A catalog you can use but not change here, such as one supplied by Epistola. A badge says why.

Finding your way

Every page has the same frame: a bar along the top that says where you are, and a side menu on the left for the place you are in.

  1. Your tenant. Click it to go back to the home page.
  2. The catalog you are in. Click it to switch to another catalog.
  3. What you are changing. Nearly always the next release. Its menu also holds published releases, trying your work on an environment, and parallel work for big changes.
  4. What is not published yet, and Publish… to make a release of it.
  5. Help: this page.
  6. Your account: your profile, switching tenant, the API docs and logging out.

I want to…

Change a letter, an invoice or another document

Open its catalog and go to Templates. Pick the template, then choose Open editor on the variant you want to change. The editor saves as you work, and the preview beside it shows the result with the example data.

See what I have changed

The bar at the top says what is not published yet. The catalog's Overview lists each change.

Let applications use my changes

Choose Publish… in the bar at the top. It tells you what will be published and makes a release. Then deploy that release on the catalog's Deployments page, or on the page of an .

Try a change before I publish it

The preview in the editor shows the document straight away. To try it the way an application gets it, open the menu on Next release in the bar and choose Try it on an environment…: a test environment then uses your work as you save it. Production only ever uses releases.

Go back to an earlier release

Open the and undeploy the newer release: the environment goes back to the release deployed before it. Is the earlier release not deployed there any more? Deploy it again first.

Use the same letterhead or footer in many templates

Make it a stencil, in the catalog's Stencils, and place it in each template. Changing the stencil changes every template that uses it.

Change fonts, colours or the page size

Go to the catalog's Themes. A theme is shared, so one change applies to every template that uses it.

Make a template in another language

Open the template and choose New variant on its Variants tab. Give it the language, and design it like any other.

Connect an application

The application needs an and a release deployed to an environment. The API tab of each template shows exactly what the application should send.

Find a document that was made

lists the documents that were made, newest first, with whether each one succeeded.

Work on a big change without holding up small ones

Open the menu on Next release in the bar and choose Start parallel work…. The big change is kept apart while small fixes are published as usual. The bar turns amber while you are in it, so you always know.

Open something I can't see or change

What you see depends on your role. Places on this page without a link are ones your role does not include. Your administrator can give you access.

Your first document

  1. Pick a catalog. Open one from , or make one with New catalog.
  2. Create a template. In the catalog's Templates, choose New template. On its Data contract tab, describe the details your application will send and add an example.
  3. Design it. Choose Open editor. Add text, tables and images, and put the details from the data where they belong. The preview shows the result.
  4. Publish. Choose Publish… in the bar at the top.
  5. Deploy. Deploy the release to an environment, for instance Test.
  6. Make a document. Try one on the 's page, or let your application ask for it.

Good to know

  • Saved is not published. Your work is kept as you go, and applications see it only once it is published and deployed.
  • A release never changes. To change one, change the next release and publish again; the new release gets a higher number.
  • Catalogs can use each other. A catalog can use stencils and themes from another, which its Dependencies page shows.
  • Some catalogs are read-only. You can use them in your templates, but not change them here.
  • Your role decides what you see. Someone else may see menu items you don't.
  • What's new? The changelog, in the footer at the bottom of every page, says what changed in each version of Epistola.
