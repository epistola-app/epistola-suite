title: The catalog page is organised around the next version, with a page for every version.
---

A catalog's page now starts, for a new catalog, with the steps from here to a document your application makes: add a template, publish it and make it live, and the keys your application asks for. Then the **Next version**: where you work, based on the latest published version, with what is not published yet and a Publish button — its number is picked when you publish. When something has to go out before the next version is ready, **Start an in-between version** begins from the latest published version without your unfinished changes. What the next version holds is shown by kind — templates, stencils, themes, images, fonts, attributes, code lists — each with a button to add one right there. **From other catalogs** shows what the version uses from other catalogs and at which version, and publishing records a catalog you picked something from instead of refusing. **Versions** lists every draft and published version, each with its own page: a draft's page has what is not published yet, its contents and its details; a published version's page says where it is live and offers export and a draft from it. Publishing can make the new version live in the environments you tick, so changing a template and having your application use it is one step. **Live** shows which version each environment uses, with Make live and Take offline. The tenant's home page uses the same words.

The environment page uses the same words: what is **live here**, **Make live**, **Take offline**, and a history of what was made live or taken offline.
