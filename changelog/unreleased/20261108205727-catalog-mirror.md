title: Tenants can share their released catalogs with Epistola for release checks (alpha).
---

With the support connection on, tenants named (not confidential) and the catalog mirror granted by
Epistola, a tenant can share its released catalogs with Epistola, which checks them against new suite
versions before it releases one. The choice is a step of the tenant's setup wizard on its Support
page: every catalog (new ones included) or only the catalogs it marks; under Support → Catalog mirror
each catalog can be marked Share or Never share. An installation administrator can set it up for every
tenant, or forbid it, under Setup for every tenant (Helm `support.tenantDefaults.mirror`).

The installation keeps the support service's copy in step every 15 minutes, one node at a time:
released versions only, never drafts, with every release they depend on, also from catalogs that are
not shared themselves. Epistola's own catalogs (the system catalog and bundled ones) follow the
tenant's choice like any other. A release that depends on a catalog marked Never share is not sent,
and the page says which catalog holds it back. Content the support service already holds is not
uploaded again, and what stops being shared is deleted there. Making tenants confidential withdraws
everything the mirror holds. `epistola.support.mirror.enabled=false` (Helm `support.mirror.enabled`)
stops sending for the whole installation; withdrawals still run. See docs/catalog-mirror.md.
