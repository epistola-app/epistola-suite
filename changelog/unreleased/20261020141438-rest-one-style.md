title: The REST API speaks one style for names, enums, paging, updates and limits.
---

Enum values are lowercase kebab-case (`in-progress`, `api-key`). Names follow the contract: a variant's `title` and a code list's `displayName` are `name`, a document's `id` is `documentId`, a page's count is `page.total`. Generation job items, code-list entries and available releases are listed a page at a time. Updates accept `If-Match` against the `ETag`, every create answers `Location`, and an omitted or null member keeps its value. Lists, maps and texts have the contract's limits, also in the web UI and MCP. **Action on upgrade:** move REST clients to the 2.0 names.
