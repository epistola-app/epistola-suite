title: The REST API speaks one style: lowercase enum values, `total` counts, ETags on every update and `Location` on every create.
---

Every enum value on the wire is lowercase, kebab-case when it has several words: job and item `status` (`pending`, `in-progress`, `completed`, `failed`, `cancelled`), `jobType` (`single`, `batch`), a collected result's `status`, code-list `sourceType` (`inline`, `url`) and `authType` (`none`, `api-key`, `bearer`), the missing-dependency reason (`unavailable`), the ping `status` (`up`, `degraded`) and the catalog type (`authored`, `subscribed`). A page's count is `page.total` (was `totalElements`) and a job's `total` (was `totalCount`); a collect response's meta line says `resultCount` (was `count`). A collected result now has the contract's member names (`templateKey`, `variantKey`, `versionId`) and names its catalog (`registry`, `namespace`, `catalogKey`). Tenants, environments and catalog versions get an `ETag`, and their updates accept `If-Match` and answer 412 `resource-modified` when the resource changed since: `updateTenant`, `updateEnvironment`, `updateCatalogDraft` (the former `renameCatalogDraft`, which also sets the default theme and presets) and `updateCatalogDependencies` (both against the version's `ETag`), and `updateCodeListEntryHidden` against the code list's. Every create answers with the new resource's address in `Location`, and an accepted generation with its job's. `listDocuments` filters by catalog (`registry`, `namespace`, `catalogKey`), and a listing by `templateKey` needs `namespace` and `catalogKey` (400 otherwise). Deleting a theme that the version still uses, as its default theme, a template's theme or a variant's override, is refused with 409 `theme-in-use` instead of leaving them without it. **Action on upgrade:** move REST clients to the 2.0 contract release.
