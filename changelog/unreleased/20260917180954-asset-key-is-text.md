title: An asset's key is text, like every other catalog resource's.
---

Assets were the one catalog resource addressed by a UUID rather than a readable key, which is why
a catalog that names its images readably — `municipality-mark` — could not be installed: the
importer parsed the slug straight back into a UUID. `assets.id` is now text, matching every other
resource. Existing data needs no migration, since an asset's current key is already a valid UUID
string. Nothing can yet create a readable key — that needs the REST surface to represent one first
— so this changes no observable behaviour on its own.
