---
type: fix
scopes: [catalog]
title: A catalog installed from its source URL is checked as any archive is.
---

Subscribing to a catalog by URL (`https:`, `file:` or `classpath:`, the bundled system and demo
catalogs included) and upgrading it now go through the same path as an uploaded archive, a release
registry and the Exchange (contract ADR 0008, "installing is importing"). Its fingerprint is
recomputed, every image and font file is checked against its content hash, the releases it pins
must be present, and a resource its content refers to must be in the catalog. Before, such a
catalog was installed without those checks.

An upgrade from a source now behaves as receiving any release: with no changes of its own, the next
version moves to the new release and what the publisher no longer publishes is removed, unless
another catalog uses it. With changes of its own, the release is recorded beside the next version,
to be merged, where the upgrade used to be refused. A source that cannot serve a file refuses the
install whole, before anything is written.
