title: An API key is sent only as `Authorization: ApiKey <key>`; the `X-API-Key` header is no longer read.
---

Contract 2.0 defines one way to send an API key, the `Authorization: ApiKey` scheme, and the REST API and MCP endpoint now accept only that: a request that sends its key in `X-API-Key` (or in a header named by `epistola.auth.api-key.header-name`) is treated as unauthenticated. The `epistola.auth.api-key.header-name` setting is removed. **Action on upgrade:** send API keys as `Authorization: ApiKey <key>`; the 2.0 client libraries already do.
