title: An API key is sent only as `Authorization: ApiKey <key>`; the `X-API-Key` header is no longer read.
---

Contract 2.0 defines one way to send an API key, and the REST API and MCP endpoint accept only that: a key sent in `X-API-Key`, or in the header `epistola.auth.api-key.header-name` named, is ignored. That setting is removed. **Action on upgrade:** send API keys as `Authorization: ApiKey <key>`; the 2.0 client libraries already do.
