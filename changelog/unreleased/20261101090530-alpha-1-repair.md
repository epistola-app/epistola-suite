title: A database 2.0.0-alpha.1 migrated needs a repair script before a later 2.0 version starts.
---

1.x let you archive a stencil version that published templates used. The upgrade left a stencil with no published version out of the "Published in 1.x" draft even when a published template there used it, so that draft could not be released; it now holds the stencil as its latest archived version. A stencil instance turned into plain content also lost the styles set on the instance, such as keep together or a margin; it now becomes a container keeping them (content alpha.1 converted stays as it is). Because upgrade steps changed, a later version refuses to start on any database alpha.1 migrated, changing nothing. **Action on upgrade from alpha.1:** stop alpha.1 and run `docs/upgrades/2.0.0-alpha.1-repair.sql` once (Upgrades guide, "From 2.0.0-alpha.1"); it records the corrected steps, adds the missing stencils, and replaces the read model's views of the catalog version a statement means with functions that take it as arguments, as the corrected read-model migration (`V20261101001500`) now creates them: the schema no longer reads the version from session settings (ADR 0049). A database rebuilt from 1.x or from scratch needs nothing.
