title: An environment uses deployed catalog versions, replacing per-template activations.
---

In 1.x an environment activated a version of each template. In 2.0 you deploy a published version of a catalog to an environment: from the environment's page, from the catalog's **Deployments** page, or by ticking environments when you publish. Deploying a version adds it beside those the environment already serves, so applications asking for an older version keep getting it; a request through the environment gets the highest it serves, or the highest that matches the request's `version`. Tick **Stop using the catalog's other versions here** (REST: `replace=true`) to replace them instead. Each deployed version shows how much it is used: how many documents were requested through the environment from it, and when the last was (REST: `documentsRequested`, `lastUsedAt`), so you can undeploy a version once nobody asks for it. A deployed version uses the versions of other catalogs it was published with without them being deployed: the environment page lists them under **Comes along**, and deploying with its dependencies deploys them as well. **Use as latest** makes one of the versions an environment serves the one documents get when they ask for no exact version, for a rollback or to hold back a newer one; **Use the highest again** undoes it. The publish dialog never ticks a production environment for you. A test environment can also follow the next version or long-term work (**Try it on an environment…**): its documents come from the work as it is changed, carry the preview watermark and say which work they came from. An environment marked **production** uses only published versions. The environment's history records every deploy, undeploy and change of what it uses, with who made it. A version an environment uses cannot be deleted, and an environment that serves versions cannot be deleted. **Action on upgrade:** activations are not carried over, so every environment starts with nothing deployed and refuses document requests until you deploy; environments keyed or named `production`, `prod`, `prd` or `productie` are marked production.
