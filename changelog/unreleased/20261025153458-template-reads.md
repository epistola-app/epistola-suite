---
type: feat
scopes: [templates, catalog, storage]
title: A release's templates read like a draft's, through REST and MCP too, and a draft stores each template model as its release does.
---

The template, variant, content and data-contract reads now answer a release as well as a draft: the REST template endpoints read a release through the same queries as a draft, paged in the database, and the MCP `list_templates`, `get_template`, `list_variants`, `get_variant` and `get_data_contract` tools take a release number as `catalogVersion`. A release's variant content now names references into the template's own catalog with that catalog, as a draft's always has. A draft stores a template model the way its release keeps it, with references into its own catalog relative, so a draft and the release cut from it hold the same model; a moved template's models keep their meaning.
